# FPT Knowledge v1.0.2

Download the Windows-Portable ZIP, extract it, then open **FPT Knowledge.exe**.
Flutter, a terminal, FLM login, and your own AI API key are not required to start.

## Changes

- Connect to FLM retains the existing login and opens Database Update directly.
- One **Check for Updates** action inventories visible curriculum IDs, resumes
  verified downloads, validates a staged merge, and refreshes offline search/counts.
- Quick checking downloads missing new details, not unchanged syllabi. Optional
  deeper checking compares existing visible details when requested.
- FLM option slots such as `EL_CK*1` stay options, not invalid subject IDs.
- Explicitly report syllabi for which authenticated FLM returns zero results;
  keep the curriculum rows and existing database without inventing missing content.
- Atomic local installation, retained checkpoints/recovery copy, and integrity
  hashes protect the working database. A smaller visible inventory never deletes it.
- Hide legacy collector tools from the student release. Preserve My Curriculum,
  My Notes, Obsidian integration, offline browsing, and the existing direct Groq AI.

## Data scope and limitations

The immutable bundled offline baseline remains 490 curricula / 1,313 subjects /
451 specialization curricula. Authenticated additions are local to each student;
their login/session and local collection are not uploaded in this release.

The real authenticated check exposed 502 curriculum IDs. Against the installed
baseline, 27 were new and 15 older installed IDs were not visible; none were removed.
The verified local merge produced 517 curricula / 1,313 subjects / 478 specialization
curricula. All 2,293 prior academic-record hashes stayed unchanged.

FLM returned no visible syllabus for `HMR101C` and `HMR201C`. These are reported
as unavailable, not fabricated or silently declared synchronized. Quick checks cache
that availability for 24 hours; deeper checking retries immediately.

The list has codes and decision-number/date fields, not an authoritative content
revision. An ID-only check cannot certify that existing contents are unchanged.
The measured no-new-ID check took 8.972 seconds, made zero detail downloads, and
observed two list snapshots (~3.44 MB uncompressed HTML; not measured wire bytes).
Real modified-content handling was tested with fixtures, not by modifying FLM.

Compiled direct-Groq credentials remain extractable, as accepted by the owner.
AI needs internet. The bundled FLM dataset is redistributed with owner permission;
this is an independent student project, not an official FPT service.
